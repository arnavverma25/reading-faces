Chapter six, algorithm and code.

The algorithm has seven steps and runs once for every camera frame. Find the face. Measure how big it is and how far it is turned. If the view is too poor, stop and tell the user. Otherwise, score each expression. Blend the scores into a running average, and let poor frames count less. Pick a label only if the average is clearly above the threshold. And speak only when the label changes.

The Python program on this page does exactly that. It uses Google's Face Landmarker to get landmarks, blendshape values and the head angle. The scoring function is a set of Action Unit rules. It compares the face with the same person's resting face, so only the change counts. For example, the smile score is how far the mouth-smile value has risen.

I chose rules because you can read them. A trained network is more accurate, and you can swap it in by replacing one function. The page lists that and the other alternatives.

The program does not detect masks or glasses, and it handles one face only. Those are the next things to add.

The algorithm

These steps run once for every frame that the app decides to process.

  1. Find the face and its landmarks. No face: report it once and wait.
  2. Measure the view: face width in pixels, and the head angles yaw and pitch.
  3. Gate. Too small or turned too far: skip the classifier and report “cannot see the face well”. Otherwise give the frame a trust value from 0.3 to 1.
  4. Score. Compare the face with the same person's resting face, measured during the first second and a half. The result is five scores that add up to 1, one per label.
  5. Smooth. Blend the scores into a running average. Low trust moves it less.
  6. Decide. Highest average above the threshold: that is the label. Otherwise “not sure”.
  7. Speak only when the label changes to a new expression.

The code

The program is about 200 lines of Python. The parts below hold the logic; the rest opens the camera and calls Google's Face Landmarker as its documentation describes [4]. Download the full file.

Step 4: scoring with Action Unit rules

Several of the 52 blendshape values match Action Units closely, so rules like those in Chapter 3 can be written down. The program first reduces the blendshapes to eight features.

def features(blend):
    """Reduce the 52 blendshape values (each 0 to 1) to the eight that the rules
    use. Left and right are averaged. Each one is close to an Action Unit."""
    def both(name):
        return (blend.get(name + "Left", 0.0) + blend.get(name + "Right", 0.0)) / 2

    brows = blend.get("browInnerUp", 0.0) + both("browOuterUp")
    lips = both("mouthPress") + blend.get("mouthRollLower", 0.0)
    return {
        "smile": both("mouthSmile"),                   # AU12 lip corner puller
        "frown": both("mouthFrown"),                   # AU15 lip corner depressor
        "jaw_open": blend.get("jawOpen", 0.0),         # AU26 jaw drop
        "brow_up": brows,                              # AU1 + AU2 brow raisers
        "brow_down": both("browDown"),                 # AU4 brow lowerer
        "eye_squint": both("eyeSquint"),               # AU7 lid tightener
        "lips_tight": lips,                            # AU24 lip pressor
        "chin_up": blend.get("mouthShrugLower", 0.0),  # AU17 chin raiser
    }

It then scores the change from the person's resting face. This matters more than I expected. On my own face the brow-lowering value is 0.35 at rest, and a rule with a fixed limit would read that as angry all the time.

def expression_scores(face, rest):
    """Step 4. Compare a face with the same person's resting face and return
    five scores that add up to 1.

    Only the CHANGE from the resting face counts, so a person whose brows sit
    low is not called angry all the time. The divisors (0.8, 0.5, 0.45, 0.4,
    0.18) are how far each feature moved on one test face for a full
    expression. They are starting values, not trained.
    """
    def rise(x):                          # keep increases, ignore decreases
        return max(0.0, x)

    def clip(x):                          # keep a score between 0 and 1
        return min(1.0, max(0.0, x))

    d = {name: face[name] - rest[name] for name in face}     # change from rest

    brow_raise = d["brow_up"] + rise(-d["brow_down"])
    tension = (d["lips_tight"] + 0.5 * rise(d["eye_squint"])
               + 0.5 * rise(d["brow_down"]))

    smiling = clip(d["smile"] / 0.8)
    surprised = clip(0.6 * brow_raise / 0.5 + 0.4 * d["jaw_open"] / 0.45)
    angry = clip(tension / 0.4)
    sad = clip((d["chin_up"] + d["frown"] - 0.5 * d["lips_tight"]) / 0.18)
    neutral = 1.0 - max(smiling, surprised, sad, angry)

    scores = [neutral, smiling, surprised, sad, angry]
    squared = [s * s for s in scores]    # squaring makes the strongest score stand out
    total = sum(squared)
    return [s / total for s in squared]

Steps 2 and 3: the view check

The third column of the matrix's rotation part is the direction in which the nose points.

def head_angles(matrix):
    """Step 2. Read yaw (turn left/right) and pitch (tilt up/down) in degrees
    from the 4x4 face transformation matrix."""
    forward = (matrix[0][2], matrix[1][2], matrix[2][2])   # where the nose points
    yaw = math.degrees(math.atan2(forward[0], forward[2]))
    pitch = math.degrees(math.atan2(-forward[1], math.hypot(forward[0], forward[2])))
    return yaw, pitch
def view_trust(face_pixels, yaw, pitch):
    """Step 3. Return 0 when the face should not be classified, otherwise a
    trust value between 0.3 and 1."""
    angle = max(abs(yaw), abs(pitch))
    if face_pixels < MIN_FACE_PIXELS or angle > MAX_ANGLE:
        return 0.0
    if angle <= GOOD_ANGLE:
        return 1.0
    return 1.0 - 0.7 * (angle - GOOD_ANGLE) / (MAX_ANGLE - GOOD_ANGLE)

Steps 5 to 7: smoothing and deciding

class Smoother:
    """Steps 5 to 7. Keeps a running average and decides when to speak."""

    def __init__(self):
        self.average = [1.0 / len(LABELS)] * len(LABELS)   # start with no opinion
        self.label = "not sure"
        self.last_spoken = None

    def update(self, scores, trust):
        """Steps 5 and 6. Blend one frame into the average (a frame with low trust
        moves it less), then pick a label."""
        a = trust * 2.0 / (WINDOW + 1)
        self.average = [a * new + (1 - a) * old for new, old in zip(scores, self.average)]

        top = max(range(len(LABELS)), key=lambda i: self.average[i])
        # hysteresis: the current label may stay a little below the threshold
        needed = THRESHOLD - 0.1 if LABELS[top] == self.label else THRESHOLD
        self.label = LABELS[top] if self.average[top] >= needed else "not sure"
        return self.label

    def cue(self):
        """Step 7. Return a word to speak, or None. Speaks only for a new,
        non-neutral label."""
        if self.label == "neutral":
            self.last_spoken = None
        if self.label in ("neutral", "not sure") or self.label == self.last_spoken:
            return None
        self.last_spoken = self.label
        return self.label
What the numbers in the code are The window, threshold and angle limits are starting values. The five divisors in the scoring rules come from one recording of my own face, so they are tuned to one person and are not validated on a dataset. Measuring the resting face removes part of the difference between people, but expect to adjust the numbers for other faces. Sad and angry are the least reliable, because on my face they differ only in small lip movements.

Why these choices, and the alternatives

My choiceAlternativeUse the alternative when
Rules on blendshapesA small trained network on the face crop [9]You want accuracy more than readability. Replace expression_scores and keep the rest.
Running averageMean over the last N frames [11], or a clip model [12]The mean is as good. A clip model needs a far stronger processor.
Angle from the matrixPose from 2D landmarks and a 3D face model (OpenCV solvePnP)Your landmark detector returns no matrix.
Every frameAdaptive frame rate [14]Battery life matters.

Which is better? For scoring, a trained network is more accurate than hand-written rules; every benchmark number in this tutorial comes from one. For the steps around it, I think the simple versions are right for a wearable: they cost almost nothing and are easy to debug. The view check and the “not sure” state matter more to a blind user than one more point of accuracy.

What this program does not do

  • It does not detect masks, sunglasses or hair (Chapter 5).
  • It follows one face only.
  • It prints words. A phone would play a sound or vibrate.
